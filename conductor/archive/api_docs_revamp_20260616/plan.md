## Phase 1: Router Integration, MCP, OpenAPI, and Generated API Client

- [ ] Task: Establish router package structure
    - [ ] Confirm package name and location, preferably `packages/api-router/`.
    - [ ] Read relevant package codemaps and current API server/type contracts.
    - [ ] Add package manifest, TypeScript config, exports, tests, and workspace wiring.
    - [ ] Preserve repo constraints: CommonJS, ES2019, strict TypeScript, and npm scripts.
- [ ] Task: Port decorator router core
    - [ ] Port decorator metadata registration from `../drumwave-integration`.
    - [ ] Port route runtime execution and router error handling.
    - [ ] Preserve support for legacy and standard decorator modes where feasible under repo constraints.
    - [ ] Add focused tests for route metadata collection, inheritance, handler execution, and error mapping.
- [ ] Task: Include MCP support
    - [ ] Port or adapt MCP endpoint support into the router package.
    - [ ] Resolve ESM/CJS compatibility risks for MCP dependencies.
    - [ ] Add tests or documented integration validation for MCP route registration and metadata.
- [ ] Task: Automated review after router core and MCP work
    - [ ] Run automated review focused on router architecture, package boundaries, MCP dependency risk, and TypeScript compatibility.
    - [ ] Address in-scope findings before adapting production API routes.
- [ ] Task: Adapt router to existing API server
    - [ ] Create an adapter from router registration to `APIExpose` / `APIRoute`.
    - [ ] Support REST methods, stream routes, payload extraction, static routes where needed, and MCP endpoints.
    - [ ] Avoid double body parsing with existing `api-server` handlers.
    - [ ] Add compatibility tests against current handler shapes.
- [ ] Task: Add strict route docs/schema metadata model
    - [ ] Define route metadata types for summary, description, tags, params, query, body, responses, errors, streams, and MCP semantics.
    - [ ] Choose and document schema representation compatible with OpenAPI generation.
    - [ ] Fail generation for migrated routes missing required metadata.
    - [ ] Add metadata coverage tests.
- [ ] Task: Automated review after adapter and metadata model
    - [ ] Run automated review focused on API compatibility, metadata strictness, and migration safety.
    - [ ] Address in-scope findings before generation work.
- [ ] Task: Generate OpenAPI from router metadata
    - [ ] Implement OpenAPI generation for REST routes.
    - [ ] Represent streams and MCP using companion docs and/or vendor extensions.
    - [ ] Emit initial OpenAPI artifacts under `dist-docs/api/openapi/`.
    - [ ] Add OpenAPI validation tests.
- [ ] Task: Generate API clients from router metadata
    - [ ] Define generated client shape and output location.
    - [ ] Support typed path params, query params, request bodies, responses, and errors.
    - [ ] Define handling for streaming and MCP endpoints.
    - [ ] Add tests comparing generated client routes with registered route metadata.
- [ ] Task: Automated review after OpenAPI and client generation
    - [ ] Run automated review focused on generated artifacts, type safety, client/server route parity, and OpenAPI validity.
    - [ ] Address in-scope findings before migrating a real API surface.
- [ ] Task: Migrate first API surface incrementally
    - [ ] Select a bounded API area, such as instance API or host API, for first migration.
    - [ ] Write/update tests for current behavior before migration.
    - [ ] Migrate routes to decorator metadata with complete docs/schema metadata.
    - [ ] Verify server behavior, OpenAPI output, and generated client output remain aligned.
- [ ] Task: Automated review after first API surface migration
    - [ ] Run automated review focused on runtime compatibility, route parity, docs/schema completeness, and generated client correctness.
    - [ ] Address in-scope findings before phase validation.
- [ ] Task: Validate Phase 1
    - [ ] Run package-level tests for `api-router` and affected API packages.
    - [ ] Run the narrowest relevant package build.
    - [ ] Record any deferred route migrations or validation limitations.
- [ ] Task: Automated review before manual verification
    - [ ] Run final automated review for Phase 1 changes.
    - [ ] Update the PR description with validation, generated outputs, and known follow-ups.
