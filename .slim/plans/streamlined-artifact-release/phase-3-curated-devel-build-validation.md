# Phase 3 — Curated Devel Build Validation

## Outcome

The protected `devel` candidate runs the curated full BDD suite once against one isolated
execution root prepared from the staged release tarballs. Phase 5 reuses the same tarball
preparation and verification tool before npm publication.

## Tasks

- [x] Define the curated full-BDD selection and local/CI command interface for the protected `devel` tarball execution root.
- [x] Verify the build identity, source SHA, staged tarball boundary, and digest-pinned GHCR image identity before launching BDD; emit a consumed-input record.
- [x] Implement bounded full-BDD shards against the single isolated tarball root, with fail-fast cancellation and no additional build.
- [x] Claim BDD execution by `(source SHA, build identity, test-matrix revision)` before scheduling shards; persist each shard's digest-bound completion evidence in candidate state.
- [x] On a workflow rerun, reuse successful shard evidence and schedule only unstarted/interrupted shards; never automatically rerun a completed full matrix. A failed completed shard makes the candidate non-admissible until a new candidate is produced.
- [x] Define the PR smoke policy separately: deterministic affected-workspace closure and a small risk-area TypeScript smoke matrix using pinned `tsx` and no package build.
- [x] Emit local digest-bound candidate BDD evidence against source/tree, build identity, staged tarball hashes, and image digests; external/GitHub attestations remain out of scope.

## Acceptance Criteria

- The same command shape supports a developer-triggered devel-build proof and CI verification.
- Full BDD executes once per source SHA/build identity and records its exact consumed inputs.
- Retrying infrastructure work cannot duplicate a completed pack or BDD shard for the same candidate state key.

## Validation Evidence

- Curated BDD selection/policy tests and source/build-identity mismatch fixtures.
- Focused local evidence: `scripts/test/release-bdd-validation.spec.js` covers matrix,
  identity/image checks, shard claim/reuse/interruption/failure, consumed-input evidence,
  candidate-root/image propagation and fallback rejection, exclusive leases, durable
  consumed-input digests, and no duplicate successful scheduling; `scripts/test/release-pr-smoke.spec.js` covers
  closure, fallback, ordering, and pinned `tsx` command policy.
- Release validation now passes the verified candidate root and digest-pinned image through
  the existing BDD environment into Docker; the validation mode rejects missing or ambient
  bindings. Active shard leases cannot be reclaimed until expiry, while successful shards
  remain reusable and failed shards remain terminal.
- The normal built-checkout 14-chunk serial BDD matrix passed at unchanged `BDD_DOCKER_MEMORY=1536m` and
  `BDD_DOCKER_CPUS=2` after the 768 MiB parent heap/transpile-only mitigation; three
  `cli-basics` and three `hub-configuration` runs passed, with maximum `hub-runtime`
  working-set at about 905 MiB.
- The tarball architecture is covered by `scripts/test/release-tarball-bdd.spec.js` for
  two-package file installation, first-party package/bin confinement, lock/path/fallback
  rejection, nested first-party lock fallback rejection, copied BDD script-closure/Cucumber
  loading, isolated-root local Cucumber `ts-node/register` dry-run smoke, canonical
  `file:./candidate/...` lock resolution, and release Docker command isolation. Limitation:
  the isolated staged-tarball root currently has focused coverage, and one full runtime proof
  using a real candidate generated by Phase 4 is still awaited.
- `scripts/release-tarball-bdd.js` is the shared prepare/install CLI and helper intended for
  reuse by the later Phase 5 tarball validation path; the former devel built-output path is
  superseded by this isolated staged-tarball root.
- Docker BDD telemetry now samples independently from container launch (1 s report / 250 ms
  short mode), persists bounded raw Engine usage, inactive-file, calculated working-set samples
  and sampling failures, awaits a final stats/inspect attempt, records host-side preflight,
  fixture, and Cucumber phase markers, and uses Docker State.OOMKilled without post-exit
  `docker exec`. The Docker Cucumber parent now uses transpile-only ts-node with a bounded
  768 MiB V8 heap, while the container remains capped at 1536 MiB/2 CPU; TypeScript correctness
  remains the separate `npm --prefix bdd run build:bdd` gate. Focused coverage is in
  `scripts/test/bdd-docker-telemetry.spec.js`, `scripts/test/bdd-options.spec.js`, and
  `scripts/test/run-bdd.spec.js`; remaining Docker coverage paths remain out-of-band for now.
