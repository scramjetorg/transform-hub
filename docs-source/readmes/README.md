# README source model

`docs-source/readmes/` contains the source templates and conventions for generating repository README files (root `README.md` and per-package `packages/*/README.md`).

## Source files

| Path | Purpose |
|------|---------|
| `README.md` (this file) | Conventions documentation. Not used as a generation source. |
| `root.md` | Source template for the root `README.md`. Contains static content sections; the generator expands a `<!-- PACKAGE-LIST -->` marker with an auto-generated package table and appends a generated-file marker. |
| `packages/<dir>.md` | Optional per-package source overlay. When present, its content replaces the auto-generated description body. The generator always wraps the output with heading, install, import, and documentation sections, and appends a generated marker. When absent, the generator creates a README from `package.json` metadata (with deterministic description overrides for stale descriptions). |

## Package README generation rules

Each package README is generated deterministically:

1. **Heading**: `# @scramjet/<short-name>` (derived from `package.json#name`).
2. **Stability notice**: If the package is listed in `docs-source/reference/curated-reference-allowlist.json` with `stability: "experimental"`, a prominent experimental notice is prepended.
3. **Description or overlay body**: From `package.json#description` (with deterministic overrides for stale descriptions) if no overlay exists. If a `packages/<dir>.md` overlay is present, its content replaces the auto-generated description body.
4. **Install**: Standard npm install section is always emitted, regardless of overlay presence.
5. **Import**: Standard TypeScript import example is always emitted, regardless of overlay presence.
6. **Documentation link**: A context-aware link to the generated reference page (if the package has an allowlisted reference entrypoint) or to `docs-source/README.md`. Links are rebased per output context (repo, dist-docs, npm).
7. **Generated marker**: `<!-- Generated by scripts/docs.js from docs-source/readmes/... -->` appended after the content.

## Link rebasing rules

Generated READMEs must produce valid relative links in four contexts:

| Context | Relative anchor | Example |
|---------|----------------|---------|
| Repository root (`README.md`) | Root-relative or docs-source paths | `./docs-source/...` |
| Package README (`packages/*/README.md`) | Relative to package dir | `../../docs-source/...` |
| npm package page | Absolute GitHub URLs | `https://github.com/scramjetorg/transform-hub/blob/HEAD/...` |
| `dist-docs/readmes/` mirror | Relative to dist-docs output | `../content/...` |

The generator uses per-context rendering: repo package READMEs and dist-docs mirrors receive link values appropriate for their location. For repo context, relative links are used (e.g., `../../docs-source/README.md` or `../../dist-docs/reference/typescript/<slug>/README.md`). For dist-docs context, links use absolute GitHub URLs or paths relative to the dist-docs output tree. For npm context, absolute GitHub URLs are used.

## Partials and includes

Reusable content snippets live in `docs-source/_partials/`. The README generator does not currently expand partial include markers; this capability is reserved for a later phase. Generated READMEs are self-contained and do not reference partials at generation time.

## Stability labeling

Experimental packages (as marked in `docs-source/reference/curated-reference-allowlist.json` with `stability: "experimental"`) receive a prominent notice:

> **⚠ Experimental**: This package is experimental. Its API may change without notice in minor or patch releases.
